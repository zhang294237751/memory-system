# 记忆管理技能

## 执行时机

此技能在每次新会话开始时，**在回答用户任何问题之前**优先执行。

## 核心文档

- **对话摘要**: `.claude/session_abstract.md`（由 SessionEnd hook 自动生成）
- **记忆文档**: 项目根目录 `item memory.md`（结构化记忆知识库）

---

## 执行流程

严格按以下步骤执行，不要跳过任何步骤。

### Step 1: 加载现有记忆文档

读取 `item memory.md`（如果不存在，跳到 Step 4 直接创建新文档）。

### Step 2: 处理备注中的删除标记

遍历「项目及业务背景」「业务规则」「UI/设计规范」「技术栈」「架构图及模块划分」「目录结构说明」六个模块中每条记忆的「备注」列：

- **若备注中包含「删除」「不采纳」「已废弃」「作废」「移除」等标记词**：
  - 将该条记忆**移动到**「删除记忆模块」
  - 在删除记忆模块中记录：原内容、原所属模块、删除日期、删除原因（取自备注）
  - 从原模块中移除该条记忆

- **若备注中包含「修改」「更新」等标记词且给出了修改后内容**：
  - 直接更新该条记忆的内容列
  - 保留备注供后续人工确认

- **若备注为空或其他普通内容**：
  - 保留不变（备注是人工定期添加的，不要自动修改）

### Step 3: 检查删除记忆模块

读取「删除记忆模块」中所有已删除的记忆。在后续 Step 5 提取新记忆时：

- **凡是被删除过的方向/主题**，不要再作为新记忆写入。
- 例如：删除模块中有「使用 Redis 作为缓存」的记录 → 后续不再记录任何关于 Redis 的缓存选型建议。
- 但如果是**全新的、不同的信息**（如：之前删除的是「用 Redis」，现在讨论的是「用 Memcached」且是用户明确提出的），仍需写入。

### Step 4: 读取对话摘要

读取 `.claude/session_abstract.md`。如果文件不存在或为空，跳到 Step 6。

对话摘要应包含上一轮对话中用户和 Agent 的关键交互内容。从中提取**值得长期保留的知识**。

#### 记忆提炼核心原则

**记忆不是聊天记录。记录的是「结论和规范」，不是「谁说了什么」。**

每条记忆必须过自检：**新加入项目的开发者看到这条，能直接执行吗？6 个月后回看，还有价值吗？**

| 类型 | 错误写法（禁止） | 正确写法 |
|------|-----------------|---------|
| 引用原文 | "用户说改成顶部用 tab 切换阶段" | "阶段切换使用顶部 Tab 导航" |
| 过程描述 | "我已经把方案文档改成已确认版本" | 不记录（无长期价值） |
| 对话确认 | "收到，方向收敛成你指定的版本" | 不记录（无长期价值） |
| 状态更新 | "这版不再是分叉选项而是单一方案" | "项目管理页面使用单一方案视图" |

**应该记录的内容（每条必须是可执行的结论）：**
- 「结论/决策」：业务需求确认、技术方案决定（如：前端使用 React + TypeScript）
- 「规则/约束」：算法逻辑、计算公式、验证规则（如：金额保留两位小数，四舍五入）
- 「设计规范」：具体色值、字号、间距、圆角（如：主色 #1890FF，按钮圆角 4px）
- 「架构约定」：模块划分、接口约定、组件职责（如：API 层统一在 services/ 目录）
- 「文件规范」：目录结构、命名规则、放置约束（如：页面组件放在 pages/[模块]/）

**禁止记录的内容：**
- 任何引用原文的表述（"用户说..."、"Agent 回复..."、"确认了..."）
- 临时性的调试信息、错误日志
- 一次性的文件路径、临时测试用的目录
- 泛泛的讨论而没有明确结论
- 状态更新（"已修改"、"已完成"、"已确认"这类没有规则价值的记录）
- 已在删除记忆模块中的方向/主题

### Step 5: 按维度分类并更新记忆文档

将提取的知识点按以下 7 个维度分类写入 `item memory.md`：

#### 一、项目及业务背景
项目是做什么的、目标用户是谁、核心目标、业务场景。

#### 二、业务规则
算法逻辑、计算公式、业务流程规则、数据处理规则、验证规则。

#### 三、UI/设计规范
颜色色值、字号、字体、间距、圆角、阴影、布局参数、统一的视觉参数。
目的：确保所有页面的 UI 保持一致。

#### 四、技术栈
编程语言、框架、库、工具、版本要求。

#### 五、架构图及模块划分
系统架构、模块间关系、组件划分、接口约定。

#### 六、目录结构说明
文件放在哪里、命名规范、不允许乱放的约束、目录组织原则。

#### 七、删除记忆模块
已删除的记忆 + 不再记录的方向（此模块不需要「备注」列，改为「删除原因」列）。

**更新规则：**
- 每条记忆使用表格行记录：`| 序号 | 记忆内容 | 来源(会话标识) | 创建日期 | 备注(留空) |`
- 相似或重复的记忆应合并，不要创建重复条目
- 「备注」列始终保持为空，等待用户人工填写
- 「来源」列记录是从哪一轮对话提取的（如："2026-05-26 会话"）
- 每条记忆的「备注」列必须保留空白，**不要自动填写**

### Step 6: 写入记忆文档

将更新后的内容写入 `item memory.md`，保持表格格式整齐对齐。

### Step 7: 基于记忆回答问题

现在已经完成记忆更新，可以开始回答用户的问题了。

- 回答时优先参考 `item memory.md` 中的已有记忆
- 如果用户的提问与已有记忆冲突，优先以用户最新说法为准
- 如果记忆中有相关背景信息，在回答时主动关联
